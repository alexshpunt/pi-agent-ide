## Retained failures

1. On the baseline, both direct and native-Codemode scenarios failed: Search treated `docs:` as a filesystem path and returned `ENOENT`. The intended source was not searched.
2. The first live implementation searched literals, but a `regex:` call failed through the filesystem regex resolver with `ENOENT` for `docs:terminal`.
3. A new real-Pi regex assertion reproduced that failure before the routing fix. The docs resolver now claims its resource scope before the filesystem query resolvers.
4. One regex call issued while the second reload was still queued also failed through the old resolver ordering. It is not evidence about the reloaded final revision. Both all-guide and single-guide regex calls passed after the reload continuation arrived.

These failures are not reported as empty searches or successful coverage.
