# LPT-682: temporary-directory deletion

Delete now exempts eligible temporary descendants from external/non-Git confirmation. The temporary roots themselves, tracked/staged contents, failed Git checks inside the current project, hooks, and protected paths keep their safeguards. Move does not use the exception.

## Free verification

- `pnpm check:capabilities`: passed with 15 live IDE tools, 144 capabilities, and 64 cases. No inference.
- `scripts/tool-capability-matrix.test.ts`: all 16 tests passed, including real filesystem execution of both new case fixtures and source-clone isolation.
- Focused deletion policy, host-dialog, and temporary-setting tests: all 27 passed after the final production edits.
- Directory-transfer regression tests: all 17 passed with the exception disabled for Move.
- Targeted lint, typecheck, formatting, and `git diff --check`: passed.
- One real-Pi integration case, `cleans external system temp without dialogs while tracked temp still prompts on both routes`: passed. Both external scratch trees disappeared, tracked trees stayed, and only tracked calls requested host decisions.
- After reloading this worktree's extension, a standalone Delete and a native Codemode Delete each returned `delete: applied` for owned `/tmp` scratch trees. Filesystem checks confirmed removal. The real Herdr viewport (`w3QN:p1`, revision 102) showed both `Applied` results without a dialog or clipped result rows. The disposable loading override and scratch root were removed afterwards.

The first free fixture run exposed inherited Git metadata in the disposable source clone: the nominal non-Git case was actually inside its parent worktree, so its local replacement settings were not used. The dedicated setup now removes only that disposable clone's Git metadata. Its test confirms the frozen source keeps its Git metadata. The same initial unit invocation timed out in an existing transfer-fixture test at the default five-second limit; rerunning the focused matrix file with a 20-second test limit passed.
