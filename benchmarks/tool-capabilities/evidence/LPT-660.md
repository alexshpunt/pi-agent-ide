# LPT-660: native Codemode semantic rename

The [task](https://linear.app/alexshpunt/issue/LPT-660/make-native-codemode-semantic-rename-work-in-the-capability-sandbox) fixes an extension resolver boundary, not Pi itself.

## Cause and fix

Codemode's editor preflight asked the declaration-text resolver to resolve `symbol:task.ts#count#name`. That resolver treated `count#name` as a declaration selector and failed before Replace's semantic rename hook ran. Direct Replace reached the hook first and succeeded.

The declaration-text resolver now leaves `#name` resources to the existing guarded LSP rename hook. There is no declaration-only or identifier-text fallback.

## Deterministic checks

With installed Pi 1.1.0 and fresh matching fixtures in the capability Bubblewrap sandbox:

- Before the fix, direct Read → Replace passed. Native Codemode returned the task's exact resolver error and left the fixture unchanged. Both traces are retained.
- After the fix, both routes passed. The regression checks exact final bytes, cross-file imports and references, unchanged strings and unrelated local names, and the structured `lsp-rename` result mode.
- An invalid rename request failed and a read before the successful rename confirmed the source was unchanged.
- The resolver unit test failed before the fix and passed afterward. It covers top-level and member rename resources.

The first expanded regression run exceeded its outer 60-second test limit on the direct route. Its tool results showed a successful rename. The test limit now exceeds the bounded child-process lifetime and cleanup; the rerun passed both routes.

Other checks passed: 13 relevant unit tests, targeted lint and format checks, typecheck, package boundaries, machine-path checks after removing temporary session setup, and the free capability gate (15 tools, 131 capabilities, 58 cases). No full integration suite ran locally.
