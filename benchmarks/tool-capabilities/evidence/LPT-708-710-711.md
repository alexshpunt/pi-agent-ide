# LPT-708, LPT-710 and LPT-711

## Scope

These checks use the feature branch based on develop `6b16d3765714c57f45b67518ea4f46e31860b822`, IDE package version 0.8.0 and the installed Pi 1.1.0 runtime. They are deterministic checks, not paid model results. No model profile or paid route is verified here. There is no release publication in this task.

The user approved one PR for these three tasks. They also approved Boolean text Search inside registered result scopes. Pi core, public input schemas, benchmark fixtures and original benchmark recordings are unchanged.

## Confirmed causes

- LPT-708: direct editor batching captures arguments before `tool_call` resolves issued references. Three Deletes in one assistant response try to read the first issued UUID as a filename. Registered selections now use their existing selection execution pipeline, rather than ordinary path batching. Unknown and stale references still go through the shared source guard.
- The Search reproduction has a separate cause. Its query, `feature: "legacy​Checkout"`, has a colon prefix and an implicit Boolean condition. The scope resolver is valid, but dispatch skips its text fallback, and the text backend previously refused conditions. The fallback now receives the same verified scope; the existing Boolean engine searches each selected slice separately. Terms in gaps, adjacent ranges or neighboring lines cannot satisfy another slice's condition.
- LPT-710: grouped output counts receipts as files. It now aggregates by path, sums exact replacement-pair counts and retains each observed formatter state. Compact-output eligibility guards remain unchanged.
- LPT-711: early cancellation saves a stale-anchor result, but Pi validates the incomplete prefix before its tool hooks. The extension uses the supported final-message replacement to preserve the saved blocking result when those hooks did not run. It does not invent a valid payload or relax Insert validation.

## Deterministic evidence

- The initial batch-reference and incomplete-Insert integration regressions both failed with the reported symptoms.
- The original Unicode colon-query regression failed first with `No search resolver handled`, then exposed the backend's Boolean refusal. The approved Boolean scope regressions failed before implementation and passed afterward.
- Two grouping unit regressions failed before the unique-file fix, then passed with the existing grouping tests.
- `tests/integration/tooling-feedback.integration.test.ts`: the final focused run passed all 16 scenarios. It covers single and batched direct UUID/item consumers, bounded Search, stale references, the native Codemode file count, both canceled Insert prefixes and recovery, and genuinely missing/empty Insert payloads. The queued payload was never delivered to the transcript. Relevant lint passed too.
- Three existing direct/pending composition cases in `tests/integration/text-results.integration.test.ts` passed.
- Five relevant unit files passed 71 tests: scoped Search, Search dispatch, query recipes, grouped replacements and capability route validation.
- `pnpm check:capabilities`: 15 tools, 162 capabilities, 79 cases; no inference.
- Typecheck, machine-path checks, targeted formatting and `git diff --check` passed.
- The normal configured startup check loaded `src/pi-agent-ide.ts` exactly once, with no warnings, startup errors or session messages.

Failed setup attempts stay separate from product regressions: an automatic preflight tried to read a reference marker before it was issued; one test filter skipped all cases; one command used a nonexistent config filename. Two byte assertions initially assumed an implicit newline, although selected-line Replace owns its newline and EOF Insert adds only the supplied text. Those fixture expectations were corrected without changing mutation behavior.

## Live verification

The first interactive attempt reported three files for one path and rejected the original scoped query. `inspect_tui` also refused a pane/session mismatch. That failed attempt remains evidence; its cause was not established and is not attributed to stale Pi state.

The user chose to investigate this session before PR review. A temporary read-only probe confirmed the current runtime PID, Pi 1.1.0, session identity, canonical grouping module and one file for three receipts. It captured no user content and was removed before the final normal startup and reload. No production changes were needed during this investigation.

The current session then passed the actual routes:

- Native Codemode applied three selected replacements to one path and reported `3 replacements in 1 file`.
- Direct Search through an issued Read UUID found only the selected line for the original Unicode Boolean query; a conjunction with text outside that selection found nothing. Source bytes stayed unchanged.
- Two direct Deletes in one assistant response consumed actual Select UUIDs, removed only the selected lines and retained both files.
- Insert stopped at the stale anchor before its payload arrived, returned the saved stale reason and current anchors, and made no change. A fresh-anchor insertion recovered successfully.

The real human viewport was captured with `inspect_tui`: Herdr pane `w3D8:p2Y`, 274×108 cells, live bottom, revisions 712, 713 and 717. Counts, bounded matches, selected-line diffs and `Stale Anchor` status were readable and aligned. The temporary probe was then removed, normal startup again loaded the single canonical IDE source without errors or warnings, and an ordinary reload repeated grouping, scoped Search and early stale Insert successfully. The post-cleanup human viewport capture was revision 751 of the same pane. Exact fixture bytes were inspected; blocked insertion did not add a payload.

The finalized model/UI result is the stale rejection. An earlier raw execution-end validation event can still appear in recorded traces; the regression checks distinguish these surfaces rather than hiding that event.

## Matrix maintenance

The added executable cases cover Select-to-Delete, Select-to-Insert, scoped Boolean Search, unique-file grouping and stale Insert recovery. Parent-summary validation requires a completed successful Codemode parent, not successful child receipts alone. Final-feedback validation checks the matching finalized tool-result message instead of mistaking an earlier validation event for the model's result.

The stale Insert paid case cannot force every provider to stop at the same argument boundary. Deterministic streamed-prefix cases cover that boundary directly. The paid case and all new direct/Codemode routes remain unverified until explicitly authorized paid runs.
