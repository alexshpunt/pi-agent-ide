# LPT-642: Move effect reporting

Move now renders whole-file status from its effect, not call success. Unknown effects stay unknown. Shared text failure output no longer claims unchanged files without an explicit statement from the execution path.

## Local checks

- 35 focused unit tests passed: renderer lifecycle, failure evidence, and capability validation.
- Four real-Pi cases in `tests/integration/move-effects.integration.test.ts` passed. They cover failures before and after fixture bytes change, applied and confirmed not-applied results, direct and native Codemode routes, and text receipt failure after saving.
- The existing binary whole-file Copy/Move case passed.
- `pnpm --config.verify-deps-before-run=false check:capabilities` passed: 15 tools, 111 capabilities, 45 cases. No inference ran.
- Changed-file formatting, syntax lint, and `git diff --check` passed.
- Normal configured startup passed before reloading: one worktree IDE loader, no errors or warnings, no prompt.

The failure hook runs only in an isolated Pi process. It matches marked `.tmp/move-effects` fixtures and restores the filesystem primitive on session shutdown. It is not a production fault switch.

## Visual checks

After reloading the worktree extension, a same-file Move reported not-applied and a normal Move reported applied. Destination bytes matched the fixture. `inspect_tui` captured the human pane `w3PF:p1`, revision 50; both statuses were readable and distinct.

Separate `pi-test live --once` runs showed the real native Pi TUI for whole-file and text uncertainty. Their terminal captures showed `Effects unknown`, not a no-change claim. These isolated-process captures are separate from the human-pane capture.

A separate full `tsc --noEmit` run failed in unchanged PDF and test files; it reported no errors in changed files. No full passing typecheck is claimed.

Recorded replay differed from the integration capture only in the footer rows, not the Move panels. Replay equality is not claimed.
