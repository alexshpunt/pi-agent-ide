# LPT-667: terminal guide path investigation

## Finding

The reported `~/.pi/agent/docs/terminal.md` read was not reproduced. None of the retained attempts made a filesystem Read. The original failing trace is unavailable, so its cause remains unknown. This is a bounded non-reproduction, not proof that the observation cannot recur or that any one model is reliable.

No production prompt, Read schema, resolver, guide registration, or physical guide location was changed. Current runtime evidence already advertises `docs:` and `docs:<id>` in Read's path description and asks the agent to read matching guides. A speculative wording change is not supported by the observed path choices.
Read still has no terminal-specific example in that description. The generic virtual-guide syntax is present; the missing example alone does not establish why the original model chose a filesystem path.

## Probe

`terminal-guide-first-use` asks for a short foreground shell marker and its exit status. Its task prompt does not name a guide, documentation, or a guide path. The required route lists only Bash, leaving the agent to choose its preparatory reads from the existing system prompt and tool exposure.

The checker requires a full, completed `docs:terminal` read before the first Bash call. It allows `shell:` status inspection. It rejects unrelated Reads, partial or failed retrieval, and late retrieval after first shell use.

The native route is deliberately stricter than guide-path choice: it requires the guide read itself, as well as Bash, inside native Codemode. A correct direct guide preload therefore fails that route check. Keep this distinction when interpreting the following failures.

### Initial blocked attempts

The three completed baseline attempts could not start Bash because the local node-pty install lacked its Linux native module. The fourth attempt was cancelled after the same error. These statuses remain unchanged; they do not establish a guide resolver failure. One attempt skipped the guide. The other three explicitly read `docs:terminal` before Bash, including the cancelled attempt.

The original validator also mislabeled a returned `shell:` status read as an unnecessary resource detour. It was corrected, without rewriting earlier evidence. The PTY build was repaired locally, and the case now checks PTY availability inside its sandbox before spending inference tokens.

### Recording check

One additional attempt per profile/route verified that `runtime.json` now retains full registered tool descriptions and parameter schemas. All four read `docs:terminal` directly before successful Bash execution. Both direct routes passed. Both native routes failed the strict guide-nesting check; Luna 6 also ran Bash directly.

The actual registered Read schema in these Pi 1.1.0 runs includes the virtual-guide syntax. Registry definitions are not a replacement for the prepared declarations in the initial model request.
