# LPT-655 verification

[Task](https://linear.app/alexshpunt/issue/LPT-655/verify-tool-capabilities-and-composition-with-a-paid-model-matrix)

## Suite checks

The suite declares 108 capabilities over 15 live IDE tools and 44 cases (87 direct/Codemode routes). Paid execution stays outside ordinary tests and CI. Every case starts in a fresh clone under Bubblewrap; the development checkout is not reset or cleaned.

`pnpm check` passed: format, lint, types, machine-path checks, package boundaries, catalog, live structural coverage, and public package build. Ten free regression tests and two scripted real-Pi integration tests passed. They check route provenance, source/destination edges, actual native Codemode events, a usable AST fixture, and sandbox isolation/reset/timeout/cancellation/cleanup. Normal configured startup passed after removing the temporary local extension setup. The human-visible CLI progress was inspected with `inspect_tui`.

## Paid observations

Only `openai-codex/gpt-6-luna`, thinking `low`, was used. Installed Pi was 1.1.0; the workspace SDK was 1.0.0. Thirteen invocations retained 161 case attempts, including startup failures and a cancelled invocation with no case execution. The initial full run used the then-current 42 cases and 83 routes; later runs covered added or corrected cases.

These are **historical observations across different source digests**, not a complete run of one final revision. Case definitions and validator spelling constraints changed during calibration. A historical success does not certify a changed case, and retries do not establish reliability. No old status has been rewritten.

Six routes have no observed pass: Codemode `select-linesOf`, `stale-recovery`, `read-media`, `lsp-rename`, and both `vision-display-window` routes. All other declared case routes have at least one historical observed pass. Other model profiles were not run.

## Findings and boundaries

- Codemode `select-linesOf`: the model first preserved unwanted prefix/suffix, then omitted the selected line ending. The latest result was `NEWlast`, not two separate lines. The validator correctly rejects it.
- Codemode `stale-recovery`: the route ran, but the model replaced the complete Read selection instead of only OLD, losing other fixture lines. The byte validator correctly rejects it.
- Codemode `read-media`: the model made direct Read calls despite the requested native Codemode route. Correct media content through a different route is not verification.
- Codemode `lsp-rename`: a valid requested symbol rename reports a resource resolver error while the direct route passes. Root cause is not established. Follow-up: [LPT-660](https://linear.app/alexshpunt/issue/LPT-660/make-native-codemode-semantic-rename-work-in-the-capability-sandbox).
- Vision: the isolated Xvfb display lacks a window manager; WSL capture tries a Windows bridge that is deliberately outside the sandbox. This is not evidence of model incapability. Follow-up: [LPT-659](https://linear.app/alexshpunt/issue/LPT-659/verify-isolated-window-and-display-capture-without-host-windows-access).
- Harness corrections: reviewed Search path/include alternatives; equivalent fixture path spellings and quoted literals; real nested-event framing; correct Pi boolean arguments and vision flag; Python userbase prerequisite. The original AST fixture had one-line functions, but the scope provider emits markers only for larger blocks. A four-line function now produces usable begin/end anchors, confirmed by deterministic integration and both real model routes. These are suite/fixture corrections, not production tool changes.

The user chose to finish the suite and handle tool/environment problems separately. Production tools and Pi core were not changed. Incomplete routes stay unverified; this report does not claim that the entire capability matrix has passed.
