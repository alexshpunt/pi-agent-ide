# LPT-719 / LPT-721 evidence

## Scope

This PR fixes IDE selection batches and issued Search scopes. The related Linear source SDK update has its own PR. LPT-700 is handled in a separate benchmark PR. No paid model calls, Pi core changes, weaker schema or stale guards, historical artifact edits, or publication.

Base: develop `1922570b9882c023f284b85ac45d3bad4be46550`, IDE 0.8.0. Final deterministic and live checks use Pi 1.1.0. Earlier Pi 1.0.0 checks are retained but are not proof of the updated SDK route.

## Reproduction and correction

Four initial real-Pi cases failed: fresh same-file Replace/Delete/Insert batches lost peers, and Search treated an issued `:all:line` scope as a file path. All batch cases submit complete calls in one assistant message and check exact bytes.

The batch captures trusted selections before writes, verifies them against the immutable original snapshot, and keeps the existing overlap planner. Actual overlap and later expired-reference refusals remain covered.

Search asks its plugin-owned scope provider to resolve issued selectors. Its session store preserves numbered snapshot checks, complete all-query refresh, trusted source reads, and sparse line/match ranges. Unknown, malformed, incomplete-all, and cross-worktree scopes reject without becoming paths. A refreshed empty all-scope succeeds with no matches.

Two further live Delete/Insert cases exposed numbered `:line` inputs becoming paths inside a batch. The Search owner now registers those containing-line snapshots with the shared result store. All-selectors still use the owner's refresh path. Strict snapshots and alias-cycle guards remain in place.

A live follow-up exposed missing output selections on applied Replace/Insert batches. Per-call receipts now map only that call's changes through the final committed snapshot and verify them with the owning Read provider. Results exclude peer changes and untouched text. Empty replacement keeps its resulting position. Copy no-op and rollback evidence keep their existing behavior.
